## 하드웨어와 배선

MCU STM32F446RE, 시스템 클록 84 MHz, STM32CubeIDE 프로젝트 이름 `motorAndEncoder`. 모터 드라이버는 TMC2209이며 M2 주소 1, M3 주소 2, PB0 단선 비트뱅 UART를 사용한다.

센서는 자석 홀센서가 아닌 Omron **EE-SX954-W 광센서**, NPN 오픈 컬렉터 출력이다.

| 선 | 연결 |
|---|---|
| 갈색 | 센서 +5 V 전원 |
| 파란색 | 보드와 공통 GND |
| 흰색 OUT2 | 차광 시 LOW, 개방 시 풀업 HIGH |
| 검정색 OUT1 | 현재 회로에서 미연결 |

- 센서1 흰색 → PB10 → M2.
- 센서2 흰색 → PB13 → M3.
- 신호마다 별도의 1 kΩ 풀업 저항을 보드 3.3 V에 연결한다. 공급 레일은 공유 가능하지만 두 신호를 서로 연결하거나 저항 하나를 공유하지 않는다.
- GPIO 내부 풀업은 끄고 INPUT/NOPULL로 사용한다.
- 기존 ENC1~6 포트/차동 수신기를 통과하지 않는 별도 센서 배선이다. 기존 엔코더 포트는 유지한다.
- 과거 파란색을 신호, 흰색을 GND로 잘못 연결한 것이 지속 LOW 문제의 원인이었다. 배선 수정 후 사용자가 광센서 시험 완료를 보고했다.
- 사용자 시험에서 3.3 V 풀업으로 동작했다. 이는 제조사가 센서 출력 부하 전압 3.3 V를 보증한다는 뜻은 아니다. 과거 논의에서 PB10/PB13의 FT 디지털 입력 5 V 허용과 NOPULL/전원 조건을 별도로 확인했다. 현재 동작한 회로를 임의로 변경하지 않는다.

## 현재 피더 동작

1. 모든 드라이버를 비활성화하고 MCU/UART/센서를 초기화한다.
2. 센서 전원 안정화를 위해 100 ms 대기한다.
3. M2/M3만 TMC 설정을 검증하고 활성화한다. 설정 실패 시 두 축을 비활성화한다.
4. M2 DIR HIGH, M3 DIR LOW로 호밍 이동한다.
5. 각 센서의 BLOCKED→CLEAR 완성된 통과를 독립적으로 5회 센다.
6. 각 상태가 2 ms 유지되어야 인정한다. 부팅부터 BLOCKED였으면 첫 CLEAR는 세지 않는다.
7. 각 축은 자기 다섯 번째 CLEAR 인정 뒤 **추가 3200 STEP**을 같은 방향·호밍 속도로 출력하고 개별 정지한다. 추가 이동 중 센서 변화는 무시한다. 다른 축은 계속 자기 과정을 수행한다.
8. 두 축의 추가 이동까지 완료되면 원점 상태를 0으로 설정하고 ENC4/TIM4 수동 제어로 넘어간다. 이때 ENC4 카운터를 재동기화하여 호밍 중 입력을 가져오지 않는다.
9. ENC4는 M2/M3를 반대 DIR로 함께 구동해 내시경 피더의 전진·후진을 조작한다.
10. ENC4 입력 부호가 바뀌면 이전 대기 스텝과 변환 나머지를 모두 지우고 새 입력만 적용한다. DIR 설정 시간 10 us 후 시작 속도에서 다시 가속한다. 새 입력이 1 STEP보다 작으면 변환에 필요한 입력이 쌓일 때까지 STEP을 출력하지 않는다.

**사용자 요청으로 피더 호밍 최대 스텝수와 수동 위치 범위 제한을 제거했다. 호밍 시간 제한도 없다. 센서가 고정되거나 통과를 놓치면 호밍 이동이 계속된다. 임의로 제한을 복원하지 않는다.**

수동 제어는 상대적인 `int64_t pending_steps`와 분수 나머지를 사용하며, feeder의 `mot[].current_pos`를 지속적인 절대 위치 추적으로 사용하지 않는다.

## 최종 파라미터

| main.c 줄 | 파라미터 | 최종 값 |
|---:|---|---:|
| 89 | M2_FEEDER_DIRECTION | +1 |
| 90 | M3_FEEDER_DIRECTION | -M2, 즉 -1 |
| 93 | M23_SENSOR_UART_TEST_ONLY | 0 |
| 94 | M23_HOME_PASS_COUNT | 5 |
| 95 | M23_HOME_SENSOR_FILTER_MS | 2 ms |
| 96 | M23_HOME_RATE_SPS | 1200 STEP/s |
| 98 | M2_HOME_EXTRA_STEPS | 3200 STEP |
| 99 | M3_HOME_EXTRA_STEPS | 3200 STEP |
| 100 | M23_MANUAL_MAX_RATE_SPS | 1700 STEP/s |
| 101 | M23_MANUAL_START_RATE_SPS | 200 STEP/s |
| 102 | M23_MANUAL_ACCEL_SPS2 | 3000 STEP/s² |

줄 번호는 후속 수정 시 다시 확인한다. M2 전류 1000 mA, M3 800 mA, 마이크로스텝 16. 200 full steps × 16 = 3200 STEP/모터축 1회전이므로 추가 이동 3200은 모터축 한 바퀴이다. 기구 출력축 회전이나 피더 길이와 같다고 단정하지 않는다.

입력 엔코더 2048 PPR × quadrature 4 = 8192 counts/회전, 변환은 3200/8192 = 25/64이다.

UART는 USART2 115200 baud, 8N1. `M2/M3 HOME PASS`, `EXTRA START`, `EXTRA COMPLETE: STOP`, `HOME COMPLETE`, `FEEDER READY`를 확인한다.

## 검증 범위

- 사용자가 광센서 개방/차광 시험 완료를 보고했다.
- 최종 소스의 C AST를 실행하는 GPIO/시계/STEP/엔코더 시뮬레이션에서 11개 검사 그룹을 통과했다. 두 축의 독립 정지, 최종 각 3200 추가 펄스, 0 추가 설정, 시작 BLOCKED 처리, 종전 64000 STEP 초과, 반전 후 기존 방향 펄스 취소, 1 STEP 미만 반전, 32비트 위치 범위를 넘는 대기량을 포함한다.
- STM32CubeIDE 1.19.0 / ARM GCC 13.3으로 최종 소스를 빌드해 오류 0개·경고 0개를 확인했다. text 36428, data 516, bss 2588 bytes.
- 변경된 최종 값으로 실제 장비의 전체 호밍·수동 운전이 완료되었다는 별도 사용자 보고는 아직 없다. 빌드/시뮬레이션을 실제 구동 검증으로 표현하지 않는다.
- 기반 브랜치의 추적된 Debug 산출물은 이번 코드로 갱신하지 않았다. 배포나 플래시는 새 빌드로 수행한다.

## 다음 작업 시 참고

현재 작업은 피더 모드이다. 기존 통합 제어에서는 ENC4가 M4/M5를 제어하지만, 피더 실행에서는 ENC4가 M2/M3를 제어한다. 이후 통합 방식은 아직 결정하지 않았으며 사용자 요구를 먼저 확인한다.

수동 가속 구현은 `speed + ACCEL / speed` 정수 계산이다. 현재 max=1700, accel=3000에서는 사용되던 값이며, max를 accel보다 크게 올릴 경우 증가량이 0이 되어 설정 최고속도에 도달하지 못할 수 있다. 현재 구현을 보존하되 향후 최고속도 변경 요청에서는 이 계산을 검토한다.

사용자는 구체적인 코드 파일과 정확한 줄 번호를 선호한다. IDE 설명은 클릭/키 순서로 안내하며, 센서 연결 문제를 다시 처음부터 반복하지 않는다. 요청 없는 구조 개편, 가감속 방식 변경, 이동 제한 복원을 하지 않는다.
